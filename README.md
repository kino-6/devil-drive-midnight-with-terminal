# Devil Drive: Midnight with terminal

> 午前0時にだけ開く巨大道路迷宮「夜環」へ潜り、異形と端末越しに交渉して契約モジュールを回収する、ダッシュボードUI型ロードローグライト。

## ゲームの一言説明
- **車載端末で交渉し、契約した異形をモジュール化して走破力へ変換する** ロードローグライト。

## 世界観
- 舞台は深夜0:00〜4:00のみ接続される道路迷宮 **「夜環（やかん）」**。
- 夜環は現実の高速道路と位相が重なっており、進むたびに地形・法則・遭遇対象が変化する。
- プレイヤーは民間回収ドライバーとして夜環へ侵入し、**契約可能な存在（異形）** を発見・交渉・回収する。
- 異形は直接戦利品として持ち帰れず、**契約書式を通して車載モジュール化** したものだけが帰還後に資産となる。
- 世界観の要点は演出よりもシステム連動を優先し、以下に直結させる。
  - 夜環の不安定性 → 毎ラン変化するルート分岐
  - 異形との契約文化 → 交渉フェーズ（リスク選択）
  - 帰還後の検収制度 → モジュール持ち帰りのメタ進行

## なぜ車を使うのか
- 本作の操作対象は「人」ではなく **車両と車載端末**。
- 車を使うゲーム設計上の理由:
  - 走行中に「移動・探索・回避」を同時処理でき、テンポが出る。
  - 車載電力/熱/通信帯域など、**リソース管理を自然に導入** できる。
  - 契約結果を「乗員強化」ではなく **スロット式モジュール装着** に落とし込める。
  - ダッシュボードUI（速度計・地図・通信ログ）だけで画面設計を統一できる。

## ゲームループ
- 1ランの基本ループ:
  1. **出撃準備**: 初期車体・初期モジュール・持込リソースを選択
  2. **走行探索**: 分岐ノードを選びながら夜環を進行
  3. **遭遇処理**: 戦闘 / 交渉 / 取得イベントを解決
  4. **契約判断**: 異形と取引し、モジュール化可否を決定
  5. **ビルド更新**: スロットへ即時装着して走破構成を更新
  6. **帰還 or ロスト**: 脱出成功でメタ資産化、失敗でラン内取得物を喪失
- プレイ感の核:
  - 「この契約は今の走行を安定させるか、破綻させるか」を短サイクルで判断する。

## MVP範囲
- 目的: **1回のランが開始〜終了まで成立し、契約によるビルド変化を体験できること**。
- MVPに含む:
  - 1車体（汎用シャーシ）
  - 3章構成の簡易ラン（各章5〜7ノード程度）
  - ノード種別4種（通常戦闘 / 交渉遭遇 / 補給 / ボス）
  - 契約モジュール10種前後
  - 主要リソース3種（耐久・電力・熱）
  - 交渉UIと戦闘UIの最小遷移
  - 帰還リザルトと持ち帰り処理
- MVPでの非目標:
  - 大規模ストーリー分岐
  - ボイス・豪華カットシーン
  - 多車体運用やオンライン機能

## 実装予定の画面
- **タイトル / メインメニュー**
  - Start Run, Continue（ダミー可）, Exit
- **ガレージ（出撃準備）**
  - 車体概要、初期モジュール選択、持込確認
- **ランマップ（ノード選択）**
  - 現在位置、先読み可能ノード、章進行
- **走行HUD（ダッシュボード）**
  - 耐久・電力・熱・速度・通信ログ
- **遭遇画面（戦闘/イベント共通基盤）**
  - 敵/対象情報、行動選択、結果ログ
- **交渉画面**
  - 提示条件、こちらの提示、成功率/破綻率、契約結果
- **モジュール管理画面**
  - 所持モジュール、スロット装着、置換比較
- **リザルト画面**
  - 生還判定、回収モジュール一覧、次回解放

## 契約モジュール例
- **灰灯ナビ（Common）**
  - 効果: 次ノード候補を1つ追加表示
  - 代償: 走行ごとに熱 +1
- **逆位相インテーク（Uncommon）**
  - 効果: 補給ノードで電力回復量 +50%
  - 代償: 戦闘開始時に耐久 -3
- **赤線防壁（Rare）**
  - 効果: 1戦闘に1回、被弾を無効化
  - 代償: 発動後2ターン電力回復停止
- **零時の取立人（Rare）**
  - 効果: 交渉成功時に追加でスクラップ獲得
  - 代償: 交渉失敗時のペナルティ増加

## M.O.E.の役割
- M.O.E.（Mobile Operations Envoy）は車載端末に常駐するオペレーターAI。
- 実装上の役割:
  - チュートリアル導線（次に押すUIの明示）
  - 交渉時のリスク解説（成功率だけでなく失敗時影響を説明）
  - ラン中ログの要約（情報過多を防ぐ）
  - 世界観台詞の供給（最低限の演出）
- 設計方針:
  - 演出担当ではなく **プレイヤー意思決定を補助するUI機能** として扱う。
